# 01 — 架构决策记录

本文件是轻量决策台账。正式 ADR 可在总纲批准后放入 `docs/adr/`。

## 已确认

| ID | 决策 | 日期 | 说明 |
|---|---|---|---|
| D-001 | UI 使用 Qt Quick/QML | 2026-08-30 | 保证现代交互与动画能力。 |
| D-002 | Windows 11 优先 | 2026-08-30 | 首先在本地 Windows 11 环境开发与验收。 |
| D-003 | 支持范围限定为 Windows 10/11 | 2026-08-30 | 暂不承担 Linux、macOS 的首发兼容成本。 |
| D-004 | 旧 JS 音源插件要求 100% 兼容 | 2026-08-30 | 必须由契约测试和真实脚本证明。 |
| D-005 | 可抛弃旧内部实现 | 2026-08-30 | 不以逐文件翻译 Electron 代码为迁移策略。 |
| D-006 | 网易云 API 和 AMLL 实现可替换 | 2026-08-30 | 保留产品能力，不绑定原依赖。 |
| D-007 | 设计先行、AI 自动化实施 | 2026-08-30 | 总纲批准前不进行批量实现。 |
| D-008 | 播放器按 B → C 分阶段交付，必要时以 A 作为短期落地层 | 2026-08-30 | 首个目标是 Gapless、Crossfade、ReplayGain、EQ 和高解析；只有相关项目难以接入且能明显缩短首个可用版本时才暂降 A，成功后恢复 B，最终升级 C。 |
| D-009 | Figma 是视觉设计真源，优先采用官方 Figma to Qt | 2026-08-30 | 导出 QML 作为可再生成的表现层资产，手写包装层负责交互、状态、模型与业务绑定。 |

## 候选，尚未确认

| ID | 候选方案 | 需要的证据 |
|---|---|---|

## 已否决

| ID | 方案 | 原因 |
|---|---|---|
| R-001 | 主界面继续使用 Electron/Chromium | 与降低基础内存和进程开销的目标冲突。 |
| R-002 | 用 QWebEngine 单独承载 AMLL 作为最终方案 | 为单一视图重新引入 Chromium，除非 PoC 证明原生实现不可接受，否则不采用。 |
