# 02 — 总纲问答记录

## 已完成问答

### Q1：前端技术是什么？

- 回答：Qt Quick/QML。
- 状态：已确认。

### Q2：是否允许抛弃旧项目内部实现？

- 回答：允许。性能与可靠性优先，不机械沿用历史实现。
- 状态：已确认。

### Q3：JS 音源插件需要何种兼容程度？

- 回答：必须 100% 兼容，否则项目没有意义。
- 状态：已确认。

### Q4：网易云 API 和 Apple Music 风格歌词是否绑定原库？

- 回答：不绑定，可以采用其他开源实现或原生重建。
- 状态：已确认。

### Q5：平台范围是什么？

- 回答：只保证 Windows 10/11，先以 Windows 11 为开发和验收环境。
- 状态：已确认。

### Q6：首版播放器能力等级

- 回答：以 B 级为首个正式目标，包括基础播放、Gapless、Crossfade、ReplayGain、EQ 和高解析音频。如果关键依赖接入困难，且 A 级能明显加快首个可用版本交付，则允许短期先做 A；基础成功后恢复 B，最终升级到 C 级能力。
- 说明：A 是交付回退点，不是取消 B；C 包括 WASAPI 独占、bit-perfect、采样率自动切换和可插拔 DSP 等发烧能力。
- 状态：已确认。

### Q9（部分）：是否使用 Figma 作为设计真源？

- 回答：是。前端计划使用 Figma 设计，并通过 Qt 官方 Figma to Qt 工作流导入 QML。
- 说明：具体视觉方向和信息架构仍待确认。
- 状态：设计工具已确认，视觉规范待确认。

## 下一轮必须确认

### Q7：产品功能范围

是完整复刻 LX Music 的功能，还是以“搜索、歌单、播放、下载、歌词、本地库、设置”为核心重新定义 MVP？

### Q8：网易云能力范围

是否需要账号登录、每日推荐、私人 FM、云盘、收藏、评论、MV、一起听等完整能力，还是仅将其作为搜索与歌词服务？

### Q9：UI 方向（剩余部分）

保留 LX Music 信息架构、重新设计，还是参考 Apple Music/Material/Fluent 等现有产品？

### Q13：Rust 与 Qt 的连接策略

是否同意以 Rust-first + Qt Bridges for Rust PoC 为优先候选？PoC 不通过时，是回退到“薄 C++/Qt Facade + Rust 核心”，还是直接采用 C++/Qt 后端？

### Q10：数据迁移

是否必须迁移旧版设置、歌单、播放历史、下载任务和自定义音源配置？是否允许一次性导入后使用新数据库格式？

### Q11：性能预算

需明确目标测试机以及冷启动、空闲、播放、歌词全屏、扫描和下载场景的内存、CPU、GPU、启动时间阈值。

### Q12：发布方式

首版采用安装包、便携版还是两者都要？是否需要自动更新、签名和 GitHub Actions 自动发布？

## 回答纪律

- 一次优先讨论一个会显著改变架构的问题。
- 对用户不熟悉的领域，应给出推荐项、成本和回退方案。
- 需要性能证据的问题先设计 PoC 和基准，不凭印象决定。
