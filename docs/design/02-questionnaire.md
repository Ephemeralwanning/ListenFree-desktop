# 02 — 总纲问答记录

## 已完成问答

### Q1：前端技术是什么？

- 回答：Qt Quick/QML。
- 状态：已确认。

### Q2：是否允许抛弃旧项目内部实现？

- 回答：允许。性能与可靠性优先，不机械沿用历史实现。
- 状态：已确认。

### Q3：JS 音源插件需要何种兼容程度？

- 回答：必须 100% 兼容，否则项目没有意义。
- 状态：已确认。

### Q4：网易云 API 和 Apple Music 风格歌词是否绑定原库？

- 回答：不绑定，可以采用其他开源实现或原生重建。
- 状态：已确认。

### Q5：平台范围是什么？

- 回答：只保证 Windows 10/11，先以 Windows 11 为开发和验收环境。
- 状态：已确认。

### Q6：首版播放器能力等级

- 回答：以 B 级为首个正式目标，包括基础播放、Gapless、Crossfade、ReplayGain、EQ 和高解析音频。如果关键依赖接入困难，且 A 级能明显加快首个可用版本交付，则允许短期先做 A；基础成功后恢复 B，最终升级到 C 级能力。
- 说明：A 是交付回退点，不是取消 B；C 包括 WASAPI 独占、bit-perfect、采样率自动切换和可插拔 DSP 等发烧能力。
- 状态：已确认。

### Q9（部分）：是否使用 Figma 作为设计真源？

- 回答：是。前端计划使用 Figma 设计，并通过 Qt 官方 Figma to Qt 工作流导入 QML。
- 说明：具体视觉方向和信息架构仍待确认。
- 状态：设计工具已确认，视觉规范待确认。

### Q7：首版产品功能范围

- 回答：首个可运行版本以旧 JS 音源兼容、歌曲能稳定播放并跑通基本功能为目标，不要求一次完整复刻 LX Music。
- 解释：基本闭环暂定义为启动、在线/本地歌曲获取、队列、播放/暂停、切歌、Seek、音量、基础歌词和可理解的错误状态；最终验收清单仍需随总纲细化。
- 状态：方向已确认。

### Q8：网易云能力范围

- 回答：需要登录、每日推荐和“我的歌单”。排行榜、搜索、歌单等在线能力不必照搬旧实现，可以进入新的网易云 API 或其他更优实现，性能与效果优先。
- 重要发现：旧版自定义音源 v2 只暴露 `musicUrl`、`lyric`、`pic`，搜索与歌单来自项目内置 `musicSdk`。新项目只兼容前者的外部契约，不保留后者的内部实现。
- 状态：已确认。

### Q9（补充）：视觉方向

- 回答：基本采用 Apple 风格，具体由后续 Figma 设计确认。
- 状态：方向已确认，具体规范待 Figma。

### Q10：数据迁移

- 回答：不迁移旧版使用数据。旧项目只用于参考细节；本地音乐文件继续保留在原目录，由新项目重新扫描并建立自己的数据库。
- 这里所称“使用数据”包括旧设置、歌单数据库、播放历史、缓存、下载任务、登录状态和自定义音源配置。
- 状态：已确认。

### Q11（部分）：内存与测试机

- 回答：旧版常见占用 1 GiB 以上；新版目标低于 400 MiB。主测试机为 Windows 11、Intel Core i9-13980 + NVIDIA RTX 4060 笔记本。
- 口径暂定：统计应用整个进程树，而不只看主进程；至少覆盖冷启动后空闲、普通播放且一个 JS SourceHost 已加载、全屏歌词三个场景。
- 状态：内存目标和主测试机已确认；CPU/GPU/启动时间及峰值口径待确认。

### Q12：发布与安装包

- 回答：通过 GitHub Releases 发布；首版只需要 Windows x64 `Setup.exe` 安装版，不提供便携 ZIP，不考虑自动更新。
- 实现：CPack + Inno Setup，输入为 `windeployqt` 生成并补齐第三方依赖的部署目录。
- 状态：已确认。

### Q13：主后端语言

- 回答：确认 C++20 + Qt。Rust 仅在有不可替代的成熟库时以窄接口接入，取消 Qt Bridges for Rust PoC。
- 状态：已确认。

### Q14：本地媒体格式

- 回答：包含 FLAC、MP3 等常见格式，并参考旧版十余种格式。
- 核对：旧项目元数据列表包含 MP3、FLAC、M4A、MP4、AAC、OGG、OGA、Opus、WAV、APE、WV、AIFF、AIF、TTA、WMA；新项目逐项做全链路测试，不只检查扩展名。
- 状态：已确认。

## 回答纪律

- 一次优先讨论一个会显著改变架构的问题。
- 对用户不熟悉的领域，应给出推荐项、成本和回退方案。
- 需要性能证据的问题先设计 PoC 和基准，不凭印象决定。
