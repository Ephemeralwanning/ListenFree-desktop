# 90 — Codex 与 AI 自动化执行指南

## 新任务启动流程

任何 Codex 或其他 Agent 开始工作时，必须先输出以下检查结果：

1. 当前设计阶段。
2. 已确认且与任务有关的决策。
3. 仍未确认、可能阻塞任务的问题。
4. 本次允许修改的目录与文件。
5. 准备执行的验证命令和验收标准。

如果无法从文档得到以上信息，不得猜测架构，应先补充问答或文档。

## 实施阶段要求

总纲批准后，每个阶段都必须具备：

- 明确目标和非目标；
- 输入、输出和接口契约；
- 可独立构建的最小增量；
- 单元、集成、兼容与性能测试；
- 对旧数据和用户文件的保护措施；
- 失败时的回退方案；
- 完成定义（Definition of Done）。

## AI 生成代码约束

- 生成代码前先查找仓库内已有接口与约定。
- 不复制无法解释或无法测试的大段第三方代码。
- 外部代码必须记录上游 URL、固定版本或提交、用途和本地修改。
- 不把 QML 页面写成业务控制器；业务状态通过明确的模型和服务暴露。
- 不在 GUI 线程执行磁盘扫描、数据库大查询、网络请求、解码或大图处理。
- 不在每帧动画中执行复杂 JavaScript、分配大量对象或跨进程调用。
- 音源兼容层必须是可测试的版本化协议，不接受散落的兼容补丁。
- 数据库迁移必须可重复、可中断并保留原文件备份。
- 性能优化必须保留优化前后基准，不能只报告主观感受。

```text
你正在开发 ListenFree Desktop。请先完整阅读仓库根目录 AGENTS.md，随后按 docs/design/README.md 的顺序阅读全部必读文档。先汇报当前阶段、已确认决策、未决问题和本次任务边界。只有 docs/design/99-master-plan.md 标记为“已批准”后才可以批量实现；否则继续问答、调研或执行被明确授权的 PoC。所有架构和性能结论都必须有测试或文档证据，并在完成工作后同步更新设计记录。
```

## 文档同步要求

- 用户确认新决策：更新 `01-decisions.md`。
- 完成一轮问答：更新 `02-questionnaire.md`。
- 总纲发生变化：更新 `99-master-plan.md` 并记录变更原因。
- 引入重要依赖：后续创建并更新依赖清单。
- 产生跨模块决定：总纲批准后创建 ADR。
